## 2026-09-27 (second pass) — the first real phone session (full log: `KATZU_V2_IMPLEMENTATION_LOG.md` §10)
- **Speech input was replaced, not repaired.** `src/lib/speech/useSpeechInput.ts` (Web Speech API) is **deleted**, with `classifySpeechError`. On the Android phone this app's learners hold it failed three ways: it recorded nothing (Chrome's recogniser lost the microphone to the app's own analyser stream), it played an OS chime no page can mute, and it does not exist in Firefox. One new pipeline: `src/lib/audio/useVoiceCapture.ts` (`getUserMedia` → `MediaRecorder`, local endpointing via the pure, tested `decideStop`: 20 s ceiling / 1.2 s silence after speech / 7 s with no speech) → `POST /ai/transcribe` → `src/lib/api/workerClient.ts#transcribeAudio` → Workers AI Whisper `large-v3-turbo` (`cloudflare-stt.js`, `language: "de"`, `vad_filter`, no previous-text conditioning). App-owned feedback replaces the system chime: `triggerHaptic` plus `src/lib/audio/cues.ts` (synthesised two-note blips, peak gain 0.06, no audio asset). The microphone is released **before** the network call. `useMicLevel` gained `getStream()` so the orb's one analyser stream is also the recorder's, and `decideStop` runs on the same rAF loop.
- **`POST /ai/transcribe` is deliberately not entitlement-gated** (transcription *is* the microphone; a free learner whose session quota is spent must still be heard) — it has its own rate budget instead (`scope: "stt"`, 40/min, 800/day, namespaced so speaking never spends a conversation turn), a 400,000-character audio ceiling on top of the global 64 KB body cap, no stored audio, and an Arabic error for every failure (`STT_UNAVAILABLE` when the binding is absent, `AUDIO_TOO_LARGE`, `AUDIO_FORMAT`, `STT_FAILED`). `[ai] binding = "AI"` was already configured in `wrangler.toml`, so **no new secret or binding is required**.
- **The conversation screen was rebuilt around a structural layout, not a floating dock.** One `h-[100dvh]` column: transcript `flex-1 overflow-y-auto`, dock `shrink-0` below it — nothing can cover a message at any dock height. The suggestion panel is an on-demand 💡 pill (no always-visible strip competing with the chat). `src/features/conversation/ConversationMessage.tsx` owns the bubble (LTR-isolated German, translation toggle, speak, word tap). Auto-scroll is instant on purpose (a smooth scroll left the newest message 169 px short — measured), and a `ResizeObserver` re-pins to the bottom from the **previous** height when the dock grows. `e2e/conversationLayout.spec.ts` asserts the geometry (no message box under the dock or intersecting the orb) at 720px and 360×640 with the panel open.

The column is reconciled additively by `ensureContentColumns()` in `cloudflare-content-schema.js` (`ALTER TABLE … ADD COLUMN`, memoised per isolate, "duplicate column name" tolerated) — **additive only, by policy**; `tests/contentStudio.test.ts` still pins the column list against `src/lib/content/curriculumAudit.ts`. Placeholders were also resized for the 448px column: `w=1200&q=70` → `w=640&h=360&q=60`, measured **235,739 → 63,113 bytes** for the same first photo.
- **The error log now survives the reload it exists for.** `src/lib/utils/diagnostics.ts` mirrors errors (uncaught `window`/`promise` + the app's own `logError`) into `localStorage` (`kz-diagnostics-crashes`, cap 40) and `rehydrateDiagnostics()` restores them on install; `console` output is captured into the buffer but **never persisted** (it can carry the learner's own sentence). `tests/diagnosticsPersistence.test.ts` pins: only already-outbound entries, bounded, idempotent across reloads, and never throwing when storage is missing/full/corrupted.

## Auth flow (current)
Google Identity Services on client → raw Google ID token → `POST /auth/session` exchange → `sess_*` session token stored in Dexie `users` row → Authorization: Bearer. Auto re-exchange on 401 exists. **Raw `idToken` also remains persisted** and several calls additionally send `id_token` in the body (dual credential transport). Session revocation endpoints do not exist (TTL-only).

## Subscription flow (current)
Activation-code only **in the app**: `POST /verify` (HMAC-signed codes, KV record per code + per account) → `account:<sub>` expiry record → `/check-status`. Referral: `REF-XXXXXXXX` codes; payout on invitee's first redemption. Codes are **sold** on the separate sales site (Cloudflare Pages `katzu-sales` → `POST /crypto/checkout` → NOWPayments → `POST /crypto/webhook` mints the code). The app never takes a payment; the Pro paywall and redemption screen link out to the sales site.

## Deletion flow (current)
`POST /user/delete` revokes every session via the `sessions_by_sub:<sub>` index (worker lines 718-723) and deletes: `progress:<sub>`, quota key, `account:<sub>`, `trial:<sub>`, `email_index:*`, referral claim/history keys, the D1 `user_progress` row, `trial_quota_ledger` and `referral_payouts` rows, and the `users` registry row. **Exposed in the UI (profile settings) with an irreversible-data warning and explicit confirmation; the client wipes Dexie locally afterwards. Every step is reported so partial failures surface as retryable instead of a false success.**

- `registerType: 'autoUpdate'` → the built `sw.js` contains `skipWaiting` + `clientsClaim`, so a deploy takes over immediately rather than leaving a stale bundle against a newer Dexie schema.
- Uncaught client crashes (`window` / `promise`) POST to `/client-error` and appear in the admin error feed; console output stays on the device by design.

## AI calls (current, 2026-09-26)
**Provider pool** (`cloudflare-ai-router.js`): one hardcoded `PROVIDER_POOL` in three tiers — flagship (`gemini-3.8-flash`, `openai/gpt-oss-120b` on Groq, `gemini-3.7-flash`), mid (`gemini-3.6-flash`, `qwen/qwen3.8-27b`), lite (`gemini-3.5-flash-lite`, `openai/gpt-oss-20b` on Groq, OpenRouter `thinkingmachines/inkling-small:free`, NVIDIA NIM `openai/gpt-oss-20b` with no `rpd` because NIM publishes none). Keys come from `GEMINI_API_KEYS` / `GROQ_API_KEYS` / `OPENROUTER_API_KEYS` / `NVIDIA_API_KEYS` through one generalized parser. The router rotates within a tier before dropping a tier, rotates keys inside a provider, and bounds a whole walk to 24 s so the client's 30 s timeout cannot fire first.

**Terminal day-quota ledger (the fix):** a 429 whose body carries an explicit per-day signal (Gemini's `GenerateRequestsPerDayPerProjectPerModel`, Groq's `requests per day (RPD)`) parks that `(provider, key, model)` unit until its window resets — Gemini/OpenRouter at midnight Pacific, Groq on its rolling window. Parks persist to KV `ai-pool-ledger` (identified by non-reversible fingerprints), so a recycled isolate does not re-walk the pool; a model reported "not found" is parked for every key. Per-minute throttles keep the short cooldown, and a bare 5xx/empty completion parks nothing. NVIDIA is the one entry whose bodies name no window at all (its limits are the account-wide NIM credit allowance), so a rate-limit answer there is read as terminal by provider override and parks for the conservative hour instead of being retried on every message. **Before this**, a per-day 429 was classified as per-minute (the check compared `"per_day"` against Gemini's CamelCase `PerDay`), so a day-exhausted key was retried on every message — up to 8 models × N keys × 2 calls per learner sentence.

**Calls:** `/ai/turn` is **ONE model call since 2026-09-26** — the roleplay reply and the grammar grade travel in a single fused prompt/schema (`reply_de`/`reply_ar` first, then `evaluation`'s short fields, then the Arabic prose), which halved the provider cost of every learner message; the HTTP response shape is unchanged, so a cached PWA bundle still works. Field order is load-bearing: the model emits in `propertyOrdering` order and a long answer is cut from the END, so a response that hits the token cap loses prose, not the reply and not the grade (cap raised 1000 → 1600, then **set to 1000 on 2026-09-26**: the answer is not streamed, so the spare 600 tokens were headroom a chatty model spent, and headroom is latency). **The turn route no longer uses the shared `cleanJson`** (measured 2026-09-26): that parser is a never-throw extractor whose last resort takes the raw text, strips quotes and braces, and calls the leftovers `reply_de` with a fabricated `is_correct: true` — so a truncated fused answer appeared in a learner's chat as `evaluation: is_correct: false, original_mistake: Jaja, corrected_german: Ja, gerne!, ...` **stamped correct**, with no correction card and an invented accuracy score. `parseTurnJson` now parses strictly, repairs only provably-closed JSON (a tail cut after the reply/grade is still a usable turn), and returns `AI_EMPTY_REPLY` / `AI_EVAL_MISSING` (502 → the client's retry card) when the output cannot be trusted. `grammar_rule` is specified as a **short Arabic label** — it was being returned as an English sentence and rendered inside the RTL correction card, which reordered its own punctuation. The isolation rule tells the model to grade only the learner's final sentence. **`learner_memory` is now used (2026-09-26):** the worker had validated that field since the route was written and discarded it, and no client code ever produced it, so the tutor graded a stranger every turn while the app kept a list of exactly what its learner keeps getting wrong. `buildLearnerMemory` (`src/lib/coach/profile.ts`) groups recorded corrections by rule wording — most repeated first, spelling-only and fully-mastered rules dropped, cap 6 — and `LiveConversationScreen` sends it per turn; the worker appends it to the prompt as a **second system part** so the stable instruction keeps its cache prefix and every transport (they join parts) sees it. **The scenario opener is the one Katzu message no AI call produces**, so its Arabic is fetched separately through `/ai/translate` (`translateTextReliable`: three attempts with widening delays, each re-resolving the credential, because the first attempt races the session-token exchange at mount and a single retry could lose that race; the fetch is bounded at 12 s so a stalled worker cannot hold the bubble, and the opener's Arabic now shows by default — it is the one Katzu line a learner has no earlier turn to decode it against). The client used to seed that bubble with the **scenario title** as its "translation" (`apartment_viewing` opened with محاينة شقة under `Hallo! Willkommen. Das ist die Wohnung.`); it now shows a pending state and then either the real translation or an honest "translation unavailable — retry" affordance, never a topic presented as a translation. JSON schemas are enforced and the sanitizer strips label echoes; `/ai/hints` returns 2–4 **distinct conversational moves** with an `intent` tag each (same-move rephrasings and duplicate sentences are dropped server-side), quota-exempt; `/ai/translate` is **entitlement-gated since 2026-09-26** (it had no entitlement check at all) and caches through KV; `/ai/check-writing` is trial-counted. Workers AI is the last resort once the whole pool is parked (`AI_FALLBACK_ENABLED`), with KV-backed metrics. `/health` also reports `aiPool` (active / idle / exhausted entries + attempt counters) and the shared cache sizes. Rate limits 10/min, 200/day per account (D1-backed). 64 KB body cap at entry. Translation and hint caches are **KV-backed** (`ai-cache:*`), not per-isolate Maps — the Maps came back empty on every recycled isolate, so the same opener was re-translated after every deploy.

**Chat turn context (2026-09-26, `shapeTurnContents` in `cloudflare-ai-chat.js`):** the conversation screen sends the visible transcript, which already ends with the message being answered, and the request carried that message again as `user_message`. Concatenating the two handed the model the learner's sentence **twice, back to back** — measured on the shape in the learner's screenshot: `model: Freut mich! Möchten Sie die Küche sehen? / user: Ja / user: Ja`. That is the classic shape that makes a model answer the *previous* question, restate the input instead of replying to it, or drift off the topic the learner just raised. The route now builds `contents` itself: a trailing history entry that repeats `user_message` is dropped (case/whitespace-insensitive), consecutive same-role entries collapse to the newest, a truncated window is cut so it does not open on a reply whose question was trimmed off, and the scenario opener is exempt from that last rule because there is no question before it. Window = 3 exchanges (roleplay) / 5 (immersion), and the client no longer slices — two independent slices meant the client could trim turns the worker's window still needed.

**Measured-latency ordering (2026-09-26):** the tier walk used to be pure round-robin, so two of the three flagship entries are Gemini and most learner turns waited on whichever one the rotation landed on. `callAiRouter` now keeps an exponential moving average of end-to-end latency per `(provider, model)` and, when a handler passes `preferFast`, walks the tier fastest-first (unmeasured entries keep their rotation position behind the measured ones, and the *set* of attempts is unchanged — only the order). The turn, translate, hints and writing routes all pass it: they are the ones a learner is watching. Measurements ride the existing `ai-pool-ledger` KV blob (no extra round trip) and survive isolate recycling; a unit needs `LATENCY_MIN_SAMPLES = 3` before it is trusted, and a failed attempt records nothing. `/health` now exposes `aiPool.latency` (model + average ms + samples, no key material) so the claim is checkable in production rather than asserted. The turn payload also asks for `reasoningEffort: "low"` — reasoning tokens are latency the learner pays for and never sees — which `buildOpenAiBody` forwards as `reasoning_effort` and drops again on a 400 that names the field; the Gemini transport strips it, since Gemini rejects unknown `generationConfig` keys.

**Known residue (past the ~48 KB edit boundary, cannot be edited in place):** the legacy Gemini-only walker `callGeminiWithFailover` (head at byte 62,186) and the legacy `handleAiHints` / `handleAiTranslation` / `handleAiConversationTurn` bodies are now **unreachable** but still present; `DEFAULT_MODEL_CHAIN` survives only as a projection of `PROVIDER_POOL` because that walker references it. Deleting them requires editing the file by hand or splitting it.

## Client performance & robustness (current, 2026-09-26)
- **Route-level code splitting.** The built entry chunk was 619 kB / 183 kB gzipped — every screen and sheet in one file downloaded before the landing page could paint (Vite warned on every build). Public screens (landing, welcome, sign-in, trust) stay eager; the 15 screens behind sign-in are `React.lazy` chunks behind one `<Suspense>` fallback. Measured after: entry **424.57 kB / 135.4 kB gzip**, 21 screen chunks, 36 built chunks total, and all 36 are precached by `sw.js` (83 entries) so offline routes still load.
- **`vite:preloadError` recovery** (`src/lib/utils/preloadRecovery.ts`): splitting plus `registerType: 'autoUpdate'` means a deploy can replace a chunk a running session is about to request — the dynamic import rejects and React unmounts into the error boundary. One guarded reload recovers it, at most once per 10 s so a reload cannot loop; a blocked `sessionStorage` (private mode) still recovers.

## Documented assumptions / risks noted during baseline
- `TEST_MODE` env accepts structurally-valid JWTs without crypto verification — must never be set in production deploys. **Mitigated: the fetch entry strips it whenever `ENVIRONMENT=production`, and a test asserts the deploy config ships no `TEST_MODE`/`NODE_ENV` var. The residual risk is the second bypass trigger (`process.env.NODE_ENV === "test"`), which is inert on this deploy only because `nodejs_compat` is not enabled — do not enable it without moving that check behind the same guard.**
- Rate limiting and trial-quota locking are isolate-local (in-memory Maps) — global abuse control and hard quota ceilings are not guaranteed under concurrency.
- Admin dashboard is served as worker HTML with inline handlers and a browser-typed bearer secret.
- Local seed fixtures use a different topic taxonomy than D1 rows; quiz screens re-pull from worker on mount (stale-cache healing shipped).
